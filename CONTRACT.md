# Contrato de integração

Next App Router + React + TypeScript + pg/PostgreSQL. Projeto novo. Toda interface em pt-BR. Não usar dados demonstrativos como reais. Sem commits/push por agentes.

API JSON via `/api/[...path]` (route.ts catch-all), envelope de sucesso `{data: ...}`, erro `{error: string}` com HTTP correto. Cookie httpOnly session. GET /api/session retorna `{data: user|null}`. User público para a própria sessão: id, displayName, city, photoUrl, wcaId, role ('ADMIN'|'ORGANIZER'|'COMPETITOR'); não expor email publicamente.

POST /api/auth/register {displayName,email,password,city?,wcaId?,photoUrl?}; POST /api/auth/login {email,password}; POST /api/auth/logout {}; PATCH /api/profile {displayName,city,photoUrl,wcaId}.

GET /api/algorithms array de {id,name,category:'F2L'|'OLL'|'PLL',algorithm,variations:string[],orientation,notes,sourceUrl,sourceName,validated:boolean,method:'CFOP',puzzle:'333'}. POST /api/admin/algorithms cria, PATCH /api/admin/algorithms/:id atualiza, DELETE remove/arquiva. Apenas ADMIN.

GET /api/content objeto de strings editáveis: communityName, communityShortName, logoUrl, history, objectives, meetings, welcome, whatsappUrl, instagramUrl, contactEmail, communityPhotoUrl, communityPhotoAlt, developerBio, developerPhotoUrl, portfolioUrl, githubUrl, linkedinUrl, developerContact. Defaults sem fatos inventados, history/meetings sem conteúdo identificado. PATCH /api/admin/content {campos}. Apenas ADMIN.

GET /api/events array: {id,name,description,rules,organizerName,registrationOpen,registrationClose,status:'DRAFT'|'OPEN'|'RUNNING'|'CLOSED',published:boolean,rounds:[{id,eventId,name,puzzle:'333'|'222'|'pyram',format:'AO5'|'MO3',opensAt,closesAt,videoRequired:boolean,published:boolean}], participantCount:number}. Eventos draft apenas donos/admin. GET /api/events/:id acrescenta participants:[{id,displayName,city,wcaId}], rounds e suas rankings. GET /api/events/:id/rounds/:roundId retorna dados da rodada, scrambles:string[] somente para inscritos após opensAt, mySubmission:null|{id,attempts:[{timeCs:number|null,penalty:'NONE'|'PLUS2'|'DNF'}],videoUrl,status:'PENDING'|'APPROVED'|'REJECTED',reviewNote}, results:[{id,userId,displayName,attempts,status,averageCs:number|null,bestCs:number|null,rank:number|null}], apenas aprovados quando publicados para público; participantes podem ver estado próprio, organizador gerencia todos em admin. POST /api/events/:id/register {roundIds:string[]} (inscrição nas modalidades/rodadas).

POST /api/events/:id/rounds/:roundId/submissions {attempts:[{timeCs,penalty}],videoUrl?}; aceita substituir pelo mesmo usuário antes do prazo, reabre PENDING. GET /api/admin/events (eventos gerenciáveis mesmo encerrados); POST /api/admin/events {name,description,rules,registrationOpen,registrationClose}; PATCH /api/admin/events/:id mesmos campos e status; POST /api/admin/events/:id/rounds {name,puzzle,format,opensAt,closesAt,videoRequired}; embaralhamentos gerados no servidor com cubing/scramble e persistidos na criação, nunca expostos antes. POST /api/admin/events/:id/rounds/:roundId/publish {} apenas após encerramento e sem pendentes. GET /api/admin/events/:id/submissions retorna [{id,roundId,roundName,displayName,attempts,videoUrl,status,reviewNote}]. PATCH /api/admin/submissions/:id {status:'APPROVED'|'REJECTED',reviewNote,expectedRevision:number}; listagem administrativa e resposta de revisão incluem revision inteira, incrementada a cada reenvio, pedido de vídeo e decisão; versão obsoleta retorna 409. POST /api/admin/events/:id/participants/:userId/video-request {roundId,message} e solicitação visível em mySubmission ou round.videoRequest; usuário pode anexar URL antes do prazo, inclusive quando solicitado. GET /api/admin/audit array de {id,action,createdAt,actorId,...}. GET /api/admin/users admin only, PATCH /api/admin/users/:id {role}. ORGANIZER só próprios eventos, ADMIN todos.

Fonte do conteúdo inicial: `data/algorithms.json`, JSON array no formato acima sem id obrigatório (slug id preferível). `data/content.json` defaults institucionais. Agente backend faz scripts/seed.ts lendo estes JSON, não cria dados falsos. Rodadas 333/222/pyram com cubing/scramble randomScrambleForEvent. Acervo pequeno declaradamente incompleto.

Frontend responsável components/* exceto CubeDiagram.tsx e app/* exceto app/api/*. Backend responsável lib/*, app/api/*, db/*, scripts/*, tests/backend* e tests/scoring* etc (não tests/content*). Conteúdo responsável data/*, public/vendor/*, components/CubeDiagram.tsx, tests/content*, docs/SOURCES.md. Parent responsável package/config, README, e2e e integração.

CubeDiagram API: default export componente React com props {algorithm:string;category?:string;label:string;size?:number}. Renderiza inverso do algoritmo de solução usando cube-icons real, sem random, com amarelo U (rotacionar x2 se necessário). Disponível para frontend importar de '@/components/CubeDiagram'. Props, nomes API e banco camelCase na camada pública.

Segurança: origem comparada APP_URL para métodos de escrita, sessão aleatória armazenada hashed, scrypt password com salt, rate limit persistente, validação Zod, transações/locks para deadline e publish, URLs http(s) seguras. Use CSRF Origin obrigatório no browser (testes enviam Origin). Datas UTC no DB, UI America/Recife. Ao5 descarta melhor/pior, 1 DNF descartado, 2 DNF média DNF; Mo3 1 DNF invalida média; inteiro centésimos, +2=200, arredondamento half-up; empate por melhor individual e igualdade mantém posição. Não alegar WCA oficial.
